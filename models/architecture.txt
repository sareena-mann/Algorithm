ALGORHYTHM — TRANSITION MODEL ARCHITECTURE
==========================================
Files written: models/
Date: 2026-05-22


OVERVIEW
--------
The goal of this model is to generate seamless DJ transitions between two songs.
Given the last 15 seconds of Track A and the first 10 seconds of Track B, the model
produces a "bridge" — a newly generated audio segment that musically resolves from
A into B, matching the key, BPM, and energy of both sides.

The architecture uses Latent Space Inpainting: instead of working with raw audio
(millions of samples), the model operates in the compressed latent space of a
Neural Audio Codec. This makes generation fast and high-quality.

Pipeline:
  Raw Audio → Codec Encoder → Latent Tokens → DiT fills the gap → Codec Decoder → Audio


FILE-BY-FILE BREAKDOWN
----------------------

requirements.txt
  Lists the Python dependencies needed to run the model pipeline.
  Key packages:
    - torch, torchaudio: PyTorch and its audio I/O extension
    - descript-audio-codec: the neural audio codec (DAC) used for encoding/decoding
    - einops: tensor reshaping utilities used in the transformer
    - librosa: audio analysis (BPM detection, beat tracking) for preprocessing
    - datasets, huggingface-hub: loading training data from Hugging Face
    - soundfile, numpy: general audio and array utilities

  Install with: pip install -r requirements.txt


arch/codec.py
  Wraps Descript Audio Codec (DAC), the neural audio codec that converts raw audio
  into latent tokens and back.

  Why DAC specifically:
    DAC is a 2024 neural audio codec that encodes audio into a grid of latent vectors.
    Unlike MP3/AAC (which discard information permanently), DAC's latent space is
    designed for machine learning — the latents are smooth, continuous, and reconstructable.

  How it works:
    - encode(audio): Takes a (Batch, 1, Samples) audio tensor at 44100 Hz and returns
      (Batch, Tokens, 64) latent vectors. Each token represents 512 audio samples
      (~86 tokens per second). These are the pre-quantization continuous latents,
      which give the DiT richer gradients than discrete codebook indices.
    - decode(z): Takes (Batch, Tokens, 64) latents, quantizes them, and reconstructs
      audio via the DAC decoder.
    - secs_to_tokens() / tokens_to_secs(): Utility converters between time and token count.

  Constants:
    SAMPLE_RATE = 44100
    LATENT_DIM  = 64  (DAC 44kHz latent dimension)
    hop_length  = 512 samples per token


arch/dit.py
  The core neural network: a Diffusion Transformer (DiT) trained to denoise bridge latents.

  Architecture:
    The model is a transformer encoder that sees the full sequence:
      [context_A tokens | noisy_bridge tokens | context_B tokens]
    It outputs a noise prediction for the bridge region only.

  Key components:

    SinusoidalEmb:
      Converts an integer timestep (0–999) into a sinusoidal embedding vector.
      This tells the model how much noise is present — critical for DDPM.

    AdaLN (Adaptive Layer Norm):
      Each transformer block normalizes its input, then shifts and scales it using
      a vector derived from the timestep + conditioning. This is how the model "knows"
      what BPM, key, and genre it's working toward — the conditioning is injected
      into every single layer, not just the input.

    DiTBlock:
      One transformer layer: self-attention (every token attends to every other token,
      so context_A and context_B can directly influence what gets generated in the bridge)
      followed by a feedforward network. Both sub-layers use AdaLN.

    TransitionDiT:
      The full model. 12 DiTBlock layers, model_dim=512, 8 attention heads.
      Segment embeddings (0=context_A, 1=bridge, 2=context_B) are added so the model
      always knows which part of the sequence it's reading.
      The output projection is initialized to zero — this prevents large random predictions
      at the start of training and leads to more stable early loss curves.

    Noise schedule (cosine):
      DDPM training adds noise to the clean bridge latents in 1000 steps using a cosine
      schedule. Cosine schedules have slower noise accumulation at both ends, which
      gives the model more gradient signal on the fine details of the audio.

    add_noise(x0, t):
      Forward diffusion helper. Given clean latents x0 and a random timestep t,
      returns (noisy_latents, epsilon) where epsilon is the pure Gaussian noise added.
      The model is trained to predict epsilon.

    ddpm_sample(model, context_a, context_b, conditioning, bridge_len):
      Inference helper. Starts from pure noise and runs 1000 denoising steps,
      progressively cleaning up the bridge latents until they represent real audio.
      This is the DDPM ancestral sampling algorithm (the same family used by Stable Diffusion).

  Conditioning vector (COND_DIM = 28):
    The model receives a 28-dimensional float vector describing the transition:
      [bpm_a / 200,  bpm_b / 200,  bpm_ratio,  key_compatibility,
       genre_a (12-dim one-hot),  genre_b (12-dim one-hot)]
    This tells the model: "generate a bridge that starts at 124 BPM in house
    and arrives at 128 BPM in techno, in a harmonically compatible key."


data/dataset.py
  Defines the PyTorch Dataset classes that supply training triplets.

  build_conditioning(bpm_a, bpm_b, key_a, key_b, genre_a, genre_b):
    Converts track metadata into the 28-dim conditioning vector. The key
    compatibility score comes from Camelot Wheel adjacency rules — same key = 1.0,
    adjacent = 0.75, opposite = 0.25. This mirrors what a human DJ actually checks.

  RealTransitionDataset:
    Loads real DJ mix pairs from disk. Expects a pairs.json manifest listing
    track_a, track_b, and their metadata (bpm, key, genre). Loads the audio files,
    extracts the last 15 seconds of track A as context_a, the first 10 seconds of
    track B as context_b, and uses the overlap region as the ground-truth bridge.
    This is the "human artistry" bucket — the model learns real DJ phrasing here.

  BlendedTransitionDataset:
    The main dataset used during training. Randomly draws from RealTransitionDataset
    (if real data is available) and SyntheticTransitionGenerator with a configurable
    ratio (default 50/50). If no real data directory is provided, it runs on
    synthetic-only mode. Each call to __getitem__ returns a dict with keys:
    context_a, bridge, context_b, conditioning, source.

  Each item stores raw audio, not latents. The codec encoding happens inside the
  training loop so the dataset stays storage-efficient (no need to pre-encode terabytes).


data/synthetic.py
  Generates mathematically perfect training pairs without any real audio files.
  This is how Month 1 training works before you have a real DJ mix dataset.

  SyntheticTransitionGenerator:
    A PyTorch Dataset of N items (default 20,000). Each item is generated on the fly
    from a deterministic random seed (seed + idx), so the same index always returns
    the same pair — important for reproducibility.

  _synth_track(bpm, key, genre, n_samples):
    Builds a synthetic audio fragment using additive synthesis:
      - Kick drum: sine bursts at the start of each beat, exponential decay envelope
      - Bass: sawtooth wave at the root pitch of the Camelot key
      - Pad: filtered noise around the root frequency
    The key parameter determines the root pitch via the MIDI_NOTE lookup table,
    which maps every Camelot key to its MIDI root note. This means the model learns
    that key transitions require pitch resolution, not just volume crossfading.

  _synth_bridge(bpm_a, bpm_b, key_a, key_b, n_samples):
    Creates the ground-truth bridge: track A's synthesis fades out with a power curve
    (fade_out^1.5 for a DJ-style fast-then-slow fade), while track B fades in with
    the inverse curve. The overlap is summed, producing a clean crossfade.

  Why synthetic data matters:
    Synthetic pairs are mathematically exact — the model always knows the "right answer"
    with no human error or sloppy mixing. It learns structure and timing from synthetic,
    then learns feel and artistry from real mixes.


train.py
  The main training script. Run this to train the model.

  Flow:
    1. Loads the AudioCodec (DAC) onto the target device (MPS/CUDA/CPU)
    2. Builds a BlendedTransitionDataset
    3. Instantiates TransitionDiT (512 dim, 8 heads, 12 layers)
    4. For each batch:
         a. Encodes the raw audio batch into latents using the codec
         b. Samples a random diffusion timestep t for each example
         c. Adds noise to the ground-truth bridge latents (add_noise)
         d. Feeds context_a, noisy_bridge, context_b, t, conditioning into the model
         e. Computes MSE loss between predicted noise and actual noise
         f. Backpropagates and steps the optimizer
    5. Saves a checkpoint every 5 epochs to checkpoints/dit_epochNNNN.pt

  Details:
    - Optimizer: AdamW with weight decay 1e-4
    - LR schedule: Cosine annealing over all epochs (LR decays smoothly to zero)
    - Gradient clipping: norm 1.0 (prevents exploding gradients in the attention layers)
    - Auto-resume: at startup it looks for the latest checkpoint and picks up where
      it left off — safe to interrupt and restart
    - collate(): a custom collate function that pads bridges to the same length within
      a batch, since different pairs have different bridge durations (4–10 seconds)

  Usage:
    python train.py                            # synthetic only, 20k pairs
    python train.py --data_dir /path/to/real   # blend real + synthetic
    python train.py --synth_n 5000 --epochs 50 # smaller run for testing


infer.py
  Runs the trained model on two real audio files to generate an actual transition.

  Flow:
    1. Load two WAV files (track A and track B)
    2. Resample to 44100 Hz mono if needed
    3. Extract the last 15 seconds of A and first 10 seconds of B
    4. Encode both to latents via the codec
    5. Build the conditioning vector from the provided BPM/key/genre flags
    6. Run ddpm_sample — 1000 denoising steps from pure noise to the bridge latents
    7. Decode context_A, bridge, and context_B back to audio
    8. Apply short crossfades at the seams (4096 samples ≈ 93ms) to remove clicks
    9. Concatenate and save as a single WAV file

  The output WAV is:
    [last 15s of Track A] + [AI-generated bridge] + [first 10s of Track B]

  Usage:
    python infer.py track_a.wav track_b.wav \
      --bpm_a 124 --bpm_b 128 \
      --key_a 8A  --key_b 9A  \
      --genre_a house --genre_b techno \
      --bridge_secs 8 \
      --checkpoint checkpoints/dit_epoch0100.pt \
      --out my_transition.wav


HOW EVERYTHING CONNECTS
-----------------------

Training time:
  data/synthetic.py + data/dataset.py  →  raw audio triplets
  train.py calls arch/codec.py         →  encodes triplets to latents
  train.py trains arch/dit.py          →  model learns to denoise bridges
  checkpoints saved to checkpoints/

Inference time:
  infer.py loads two WAV files
  infer.py calls arch/codec.py encode  →  latents for both tracks
  infer.py calls arch/dit.py ddpm_sample → generates bridge latents
  infer.py calls arch/codec.py decode  →  bridge audio
  concatenated output saved as WAV


MONTH-BY-MONTH TRAINING PLAN
-----------------------------
Month 1: Run train.py on synthetic data only. Verify the model learns to crossfade
          and respect BPM/key conditioning. Loss should drop below 0.1.

Month 2: Encode your entire synthetic dataset to latents and cache them to disk
          to speed up training (remove the codec encode step from the loop).

Month 3: Add real DJ mix pairs. Wire in RealTransitionDataset. Train with 50/50 blend.
          The model learns human phrasing and energy feel on top of the structure it
          already knows from synthetic data.

Month 4: Add a discriminator (GAN-style adversarial loss) to push the model toward
          generating bridges that sound indistinguishable from human mixes.

Month 5: Quantize the model (torch.quantization or ONNX export) so it can run in
          under 500ms on Apple Silicon. Integrate infer.py as an API endpoint into
          the FastAPI backend so the web app can trigger real transitions.
